## Existing model and semantic boundary

Current `cascader.vue` renders a combobox trigger controlling a dialog, native button options inside column divs, and native button search results. Options are not currently ARIA `treeitem` or `option` roles. This product can retain that dialog/button model: virtual variants add bounded windows, stable IDs, programmatic real focus and roving tabindex to the existing actionable buttons. Do not introduce a Tree, listbox ownership claim, or `aria-activedescendant` relation through the dialog. Tests should locate the actual native buttons and typed identities rather than assume an unapproved `role="option"` rewrite.

Default `virtual` omitted/false retains the existing markup, native Tab sequence, trigger active-descendant behavior, search-input editing, sizing and keyboard rules. Virtual mode alone uses one roving button per column, one in search mode, and no trigger active descendant. The term “option” in the architecture's row-count budget denotes an actionable Cascader row, not a requirement to change its ARIA role. Any proposed richer accessibility semantics must remain valid for the retained product model and receive review before being treated as an acceptance requirement.

The parent already owns `innerOptions`, `activePath`, `focusedPath`, selected paths/tags, loading/error paths, request ids, AbortControllers, `loadGeneration`, `navigationVersion` and `keyboardRequest`. Preserve that division. Virtual children must not clone the authoritative selection or loading state and must not initiate/cancel network work simply because a row or column viewport recycles.

## Required implementation boundaries

### Public configuration and identity

- Add only `virtual?: CascaderVirtual`, `CascaderVirtual = boolean | CascaderVirtualConfig`, and configuration fields `height`, `estimateSize`, `overscan`. Export public types through Cascader and the root barrel. Omitted/false disables; true/empty plain object enables defaults **256 / 32 / 4**.
- Height and estimate must be finite positive CSS pixels. Overscan must be a non-negative safe integer, measured in logical rows per side. Validate/fallback each field independently with development warnings; reject non-boolean/non-plain runtime input by disabling virtual mode with a warning. Do not mutate caller objects, including frozen and foreign-realm plain records. Preserve public height=0 rejection.
- Reuse the installed `@tanstack/vue-virtual@3.13.36`; no dependency or lock drift, public engine object, rangeExtractor, scrollToIndex, scroll API or threshold/config-provider switch.
- Columns need an identity derived from their complete typed ancestor prefix; root is an explicitly namespaced empty prefix. A row identity adds its typed option value. Same leaf values under different parents, numeric 1 versus string "1", separators inside values and branch replacement at the same depth must remain distinct. Existing `pathToken`/`cascaderKeyToken` are the appropriate starting point; `pathKey(path.join('/'))` is a display/test attribute and must not become a cache/state identity.
- Existing column `:key="columnIndex"` and positional option IDs cannot be the virtual instance/cache/DOM identity. Index is a current position only. Stable virtual IDs include the instance id and complete typed path, in separate column/search namespaces as needed.

### Independent windows and logical state

Each column instance owns one virtualizer, its scroll element, measurement table, observation handles and cleanup. One reusable private list component instantiated independently for each typed prefix is sufficient; one shared virtualizer across all columns is not. Parent changes that replace a prefix must dispose that column and its pending work before a different branch uses the slot. Search uses a separately identified list instance with independent measurements and focus pins; mounting it must not reuse a column cache accidentally.

Selection and disabled inheritance use complete logical paths and options, not mounted DOM or leaf value/depth alone. Search remains `collectLeaves` over delivered loaded options, excluding unloaded `isLeaf:false` placeholders and inheriting disabled ancestors. Filtering does not fabricate descendants or itself request data. Changing view mode may dispose an adapter, but must not abort an otherwise valid parent-owned lazy request solely because its visual column disappeared.

One existing semantic weakness should receive an independent executable regression: `isSelected` currently compares only value at `columnIndex` and path length. With selected `['a','shared']` and active branch `['b']`, it can highlight `['b','shared']`. Full-path identity explicitly requires correct discrimination. This is a source-established baseline RED candidate, not a claimed executed failure or an architecture blocker. Test it before changing the common resolver; preserve the intended default behavior rather than freezing this wrong-path result into compatibility assertions.

### Focus, keyboard and async retirement

- Compute Up/Down/Home/End from complete enabled logical rows, never `querySelectorAll` over the current window. Preserve current column Up/Down wrapping unless the product contract is explicitly revised. Left restores the typed parent; Right/Enter/Space activate a branch/create the next column or select the leaf. Opening and input Up/Down must mount and focus an enabled target.
- Track actual-focus row, persistent roving entry and temporary pending target separately. Pin their valid union; a roving entry survives blur and ordinary scrolling. Recover/transfer before releasing a removed row. Each enabled column and the search list have exactly one mounted tabindex=0 entry; native Tab/Shift+Tab must not trap focus.
- A cross-column/search navigation request owns a generation before any nextTick, await, lazy work or column creation. It validates accepted state, logical identity, current column/mode, enabled status and component life before committing. Temporary pins/listeners retire on success, rejected request, missing target, invalidated data, capability fallback and bounded retry exhaustion.
- Use explicit request ownership. An old Home or mount callback must not retire a later same-key retry/navigation; terminal cleanup cancels only the pending generation it owns. Global popup cancellation still cancels current navigation even when a stale intent exists. Preserve the Tree/TreeSelect fixes as reference principles without importing their Tree-specific bridge as Cascader's model.
- Concrete outside focus, explicit blur, wheel/pointer/touch navigation, returning to search, accepted close, disable and unmount cancel stale focus. Distinguish browser render-removal/temporarily disabled-button focus loss from deliberate user blur; do not treat every BODY/null-related focus state as either permission to steal focus or a mandatory cancellation. A navigation cancellation alone must not abort an already-started valid loader.
- Search requires its own full-path active result: input Down/Up enters first/last enabled result; results support Up/Down, Home/End, Enter/Space, Escape, and one roving Tab entry. A 10k tail result must be selected by End then Enter. Keep Home/End native editing in the input unless an explicit separate requirement authorizes interception.
- Query changes preserve the logical active result only while that typed path remains enabled, but cancel old pending navigation. No matches keep focus in the input and expose the existing status. Clearing from a focused result restores the selected/active-path column target or first enabled fallback after mounting; clearing while the input owns focus keeps it there. Dispose old mode measurements/IDs/requests coherently.

### Lazy and controlled behavior

Keep the existing full-path request deduplication, stale response isolation and branch-switch cancellation. Existing `handleOption` establishes branch activePath before loading and returns a task awaited by keyboard child entry; preserve accepted-path validation while replacing the DOM lookup with mount-then-focus. Retry remains an actionable error option on that typed path, including after popup close/reopen or branch switching. Cover the actual visible error/selected/loading states rather than only direct loader calls.

`modelValue` and `open` remain parent-authoritative, including explicitly supplied undefined and refused updates. A refused close must not abort valid loading or optimistically remove the popup; accepted close must invalidate pending load/navigation before deferred callbacks can restart them. Keep selected value/tag state separate from active branch navigation. Cover same-turn close/unmount/disable/options replacement and loader replacement before and after starting work. The public component currently has no controlled activePath or expandedKeys API; do not invent one for this feature.

### Budget, sizing, SSR and realm safety

Reuse the private popup budget concept already added for TreeSelect; its `treeHeight` result name is internal and can be consumed as a list budget without renaming public APIs or extracting a new global framework. `useFloatingPosition` returns placement/coordinates, not an available height. Budget inputs must track final placement, owner viewport/visualViewport offset, owner resize, ancestor scroll and measured popup/search chrome. Enable new budget/adapter observation only for a real accepted-open, enabled virtual popup; clean it up on accepted close, not only after leave animation.

Pass normalized positive configuration separately from measured internal budget, which may be zero. Let observed clientHeight determine the window; do not feed zero into public normalization or substitute configured height for a genuine measured zero. Remove the virtual columns wrapper's 180px minimum when needed to shrink, use min-block-size:0/flex shrink, and prevent its overflow-x behavior from creating a second vertical scroller. There must be one vertical owner per column, or one in search mode; popup/columns wrapper may retain required horizontal scrolling. Last-column reveal remains horizontal layout work, not horizontal virtualization.

Rows are measured after hydration: 32px estimates, 44px coarse rows, wrapped/dynamic labels, font/width changes and 200% zoom. Confirm actual short/narrow geometry and last-item reachability, including search height and horizontal clipping. Unit inline styles are not geometry proof.

SSR uses normalized deterministic initial rectangles and stable typed keys; neither capability checks nor media/layout readings may select full DOM during SSR/hydration-first render. Repeated parent renderToString with defaultOpen must be byte-stable and bounded, and actual hydrate must have zero mismatch diagnostics. Parent searchText initially has no public initial-query prop; do not invent one merely to test SSR. Once present, the private search-list component can additionally have a direct SSR contract test.

All new measurement observers, RAF/timer work, events and computed-style operations use the actual viewport ownerDocument/defaultView. Cover iframe mounting and Teleport, foreign input configuration, column disposal and SPA unmount. Missing optional capabilities must not throw. Try an appropriate same-realm resize/scroll/scheduling alternative where it can satisfy the adapter; full-DOM fallback is post-hydration and must retain reachable scrolling, focus, selection and loading semantics. A virtual-configured popup must not hide a full-DOM fallback under overflow:hidden with no remaining vertical owner.

Existing shared `useMotionPresence` contains legacy global scheduling, whereas floating placement/dismissal and the new budget use owner documents. Do not blindly copy the legacy globals into new adapters or broaden this phase into a global motion rewrite. If focused iframe evidence demonstrates a required shared-tool correction, assign it to the sole production owner and rerun affected TreeSelect tests. Overlay-controller retains reusable document input listeners by design; test disposal of component-owned registrations/observers and absence of post-unmount behavior rather than demanding removal of every pre-existing global overlay listener.

The architecture's createTreeIndex duplicate/cycle guarantee protects the existing Tree model. Cascader does not currently call createTreeIndex and has a recursive clone/leaf traversal; do not introduce Tree-global key uniqueness into Cascader, where equal child values under different parents are valid. Characterize invalid sibling-duplicate/cyclic input separately and never disguise an existing data error as successful capability fallback. Valid full typed paths are the virtualization identity contract.

## Production/test ownership and handoff

One sole production implementer owns `cascader.vue`, `style.css`, `types.ts`, `index.ts`, root `src/index.ts`, and all new private Cascader virtual config/path/list/adapter files. A reusable column/search virtual-list component may be instantiated independently; names are an implementation choice, not new public API. That same owner alone may modify the shared popup budget or other shared helper if a proven requirement makes it necessary. Do not concurrently edit shared Tree/TreeSelect code or turn this into a cross-component engine refactor.

Separate test author owns new Cascader unit/type/SSR/lifecycle RED suites; separate browser author may own the query-gated fixture, E2E spec and config-selection test/routing, with explicit disjoint paths. No production test hacks, build/lock/generated edits during RED authoring. Shared build directory/server/port remains single-owner. Tests use an isolated config when needed because the components Vite closeBundle writes tracked es/lib styles; do not silently mutate accepted distributions while capturing RED.

After real RED is recorded, release the sole producer for scoped GREEN. Then rerun independent development review, maintained unit/type/SSR and five-browser checks, screenshot-first design and product acceptance. Parent phase performance, packed consumer, combined gzip and publishing requirements remain unchanged but are not executed or certified by this preflight.
